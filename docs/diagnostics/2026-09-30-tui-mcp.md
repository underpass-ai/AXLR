# TUI MCP diagnosis — 2026-09-30

> **Historical record.** This page preserves its original design or investigation context. For current behavior and operating instructions, use the [current documentation](../index.md) and its audited revision.

## Reproduction

A real pseudo-terminal ran `axlr-tui` with OpenRouter `z-ai/glm-5.3-flash`, the installed KMP and MADE stdio servers, a temporary workspace and isolated session storage. Four prompts ran sequentially: identify capabilities, read-only KMP wake, a simple reply, and read-only MADE discovery. `/mcp` and `/plugin` were exercised first. All four turns completed; KMP executed automatically, MADE discovery required one manual approval. The catalog exposed 51 tools (4 local, 16 KMP, 31 MADE). No ceremony was created or executed.

| Turn | Total | First text | Tool execution | Request bytes |
| --- | ---: | ---: | ---: | ---: |
| Capabilities | 6.32 s | 4.581 s | — | 168,883 |
| KMP wake + answer | 29.78 s | 21.150 s after tool | 64 ms | 169,506 / 172,665 |
| Simple answer | 1.73 s | 1.660 s | — | 173,290 |
| MADE discovery + answer | 21.08 s | 11.203 s after tool | 21 ms | 173,522 / 336,941 |

These are one observed run, not a latency guarantee. KMP and MADE execution do not account for the long waits. The waits were measured inside provider streaming, before text callbacks. Large tool schemas and results increase request size; their causal contribution to provider latency was not isolated experimentally. MADE discovery returned a large capability manifest, which increased the next request substantially.

An earlier real session had 11 guide reads, 32 messages and a 176,479-byte request. KMP calls there took 10–54 ms. New host context explains KMP/MADE and requests progressive guide use, while preserving complete schemas and results.

## Fixes and display behavior

- `/mcp` lists servers/tools; `/plugin` persists exact-plugin manual/automatic policies.
- Tool names remain native when unique and portable; collisions retain deterministic aliases. Authorization always resolves the frozen identity, never a name prefix.
- Unknown tools are rejected and can continue through OpenRouter; historical results need not belong to the current schema list. The current tools parameter remains present, consistent with the [OpenRouter tool-calling guide](https://openrouter.ai/docs/guides/features/tool-calling).
- Execution checkpoints precede effects. Cancellation, uncertainty and crash restoration cannot replay a started call automatically.
- Session snapshots keep assistant calls, results and following drafts in order during automatic turns.
- Tool rows and Activity show bounded previews. Full results remain in saved history and Actions → Info. KMP rows and activity have a memory style.
- The status indicates elapsed provider wait before first text, and cancellation remains available.
- Privacy-safe traces record request bytes, first text timing, tools, renders and persistence without prompt/result/key contents.

## Rendering measurement

Repeated rendering of the same saved 32-message session at 110×40, using 200 delta updates and 1,000 Views:

| Work | Before | After compact tool rows |
| --- | ---: | ---: |
| Delta refresh | about 4.7–5.4 ms | 2.25 ms |
| App View | about 1.36 ms | 0.82 ms |

This reduces local render work; it does not eliminate the observed provider wait. Streaming continues to coalesce events at 16 ms.
