# AXLR Agent Console Implementation Plan

> **Historical record.** This page preserves its original design or investigation context. For current behavior and operating instructions, use the [current documentation](../../index.md) and its audited revision.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a polished, resumable AXLR agent TUI with OpenRouter streaming, local and MCP tools, explicit per-call approval, and composed keyboard/mouse views.

**Architecture:** Extend the root AXLR library with a separate streaming model port and OpenRouter SSE adapter. Add `tui/` as its own Go module with typed session domain, application use cases and ports, AXLR/storage adapters, and a Bubble Tea v2 terminal adapter. The existing JSON worker remains unchanged.

**Tech Stack:** Go 1.26; `charm.land/bubbletea/v2`, `charm.land/bubbles/v2`, `charm.land/lipgloss/v2`, `github.com/lrstanley/bubblezone/v2`; AXLR root library; OpenRouter chat-completions SSE.

**Spec:** `docs/superpowers/specs/2026-09-29-axlr-tui-design.md`

## Global Constraints

- Root module `github.com/underpass-ai/AXLR`; TUI module `github.com/underpass-ai/AXLR/tui`; repository `go.work` uses both.
- Keep `cmd/axlr` and its one-request JSON contract unchanged. Root module gains no terminal dependencies.
- Target trusted-local Linux. Require explicit workspace root, model ID and OpenRouter key; require explicit manifests when plugins are used. Do not inherit the full environment into plugin processes.
- Every model-requested tool call needs a human decision. At most 32 tool calls per user turn; no automatic retry of uncertain tool effects.
- Streaming caps: 1 MiB per SSE event, 8 MiB aggregate response. A tool call is executable only after complete validation.
- Saved sessions use versioned snapshots, owner-only permissions, atomic replacement and an exclusive writer lock. Never persist the API key.
- One primary Go type per file where a type is needed; no `.go` files at the repository root.
- Race tests and aggregate coverage above 80% for each module; `go vet`, formatting and static builds for both executables in one cached CI workflow.

## Review Focus

1. SSE frames split between bytes of a UTF-8 character or within a tool argument must assemble before validation; Task 2 tests both boundaries.
2. A model tool name that is absent, collides with another advertised name, or changes after discovery must never execute a different tool; Task 4 tests catalog identity and Task 6 tests unknown calls.
3. A process crash during save or a second process opening the same session must not corrupt its last snapshot; Task 7 tests recovery and locking.
4. Narrow terminals, wide glyphs and untrusted ANSI sequences must not hide approval controls or alter terminal state; Task 8 tests layout and sanitization.
5. Cancellation during an in-flight tool call must leave its outcome explicit and avoid a retry on resume; Task 6 tests that transition.

- Module/domain: `go.work`, `tui/go.mod`, `tui/domain/` value-object and aggregate files, and tests. Reuse root `domain.Message`, `ModelID`, `ToolCallID`, `ToolDefinition` and `JSONValue`.
- TUI application: `tui/application/` port interfaces, `continue_turn_use_case.go`, `start_turn_use_case.go`, `resolve_tool_use_case.go`, `search_session_use_case.go`, and tests.
